# code-family-2-elm.md — `Code` + `Equation` + `Log` Elm-side design

Read after code-family-1-upstream.md. Targets: `src/NUI/Code.elm`, `src/NUI/Equation.elm`,
`src/NUI/Log.elm` (all single-module — LogLine/LogLoader are private helpers inside Log.elm).
Theme modules `src/NUI/Theme/{Code,Equation,Log}.elm` generated by the pipeline.

House patterns this leans on: `NUI.Highlight` (no-css component + raw-Html root + `innerHTML`
via `Element.html`/`Html.node`), `NUI.Spin` + `NUI.Internal.Loading` (spinner svg; wrapper
divs caller-owned), `NUI.Scrollbar` (the scroll seam Log embeds), `NUI.Carousel` (NEWEST:
Options record, raw-Html subtree via `Element.html` when cssr owns layout), `NUI.Upload`
(raw `<input>`, empty-string option → EN locale default), `NUI.Empty` (localized default via
`Maybe String` override), `NUI.BackTop` (caller-owned `Maybe I.TransitionPhase`).

## 0. Verdict

Three small modules, no Internal engine split. `Hljs` is a shared record type — define it in
`NUI.Code` and let `Log` import it (Log already embeds Code). `innerHtml` is a 2-line private
helper in `Code.elm` and `Equation.elm` (`HA.property "innerHTML" (Json.Encode.string s)`);
a shared `NUI.Internal.innerHtml` is an option but not required. `elm/url` becomes a **new
library dependency** for the URI-decode decision (see §5, and the brief-assumption correction).

## 1. `NUI.Code`

### 1.1 Types & module surface

```elm
module NUI.Code exposing
    ( Hljs
    , Options
    , codeHtml
    , cssVarsFor
    , defaults
    , lineNumbers
    , mergedShowLineNumbers
    , view
    )

type alias Hljs =
    { getLanguage : String -> Bool
    , highlight : String -> String -> String   -- highlight code language -> hljs html STRING
    }

type alias Options msg =
    { language : Maybe String            -- undefined
    , code : String                      -- ''
    , trim : Bool                        -- TRUE (⚠ Log's is False)
    , hljs : Maybe Hljs                  -- Nothing
    , uri : Bool                         -- False
    , inline : Bool                      -- False
    , wordWrap : Bool                    -- False
    , showLineNumbers : Bool             -- False
    , internalFontSize : Maybe Int       -- Nothing (Log passes Just fontSize)
    , internalNoHighlight : Bool         -- False (Log passes True)
    , attributes : List (Html.Attribute msg)   -- ROOT is raw Html ⇒ Html, not Element
    }

defaults : Options msg
-- all of the above, `code = ""`, `trim = True`, every Maybe Nothing, every Bool False, attributes [].
```

`highlight` arg order is `highlight code language` (mirrors upstream
`hljs.highlight(code, { language }).value`). `getLanguage` returns a Bool (upstream returns the
language object; the port only ever truth-tests it). Examples/tests supply a deterministic toy
record — e.g. `{ getLanguage = (== "javascript"), highlight = \c _ -> "<span class=\"hljs-keyword\">" ++ c ++ "</span>" }`.

### 1.2 Pure mirrors (pins-first targets)

```elm
-- createCodeHtml (Code.tsx:41-56): the two gates, in order.
codeHtml : Maybe Hljs -> Maybe String -> Bool -> String -> Maybe String
codeHtml hljs language trim code =
    case hljs of
        Nothing -> Nothing                                          -- GATE 1
        Just h ->
            case language of
                Just lang ->
                    if h.getLanguage lang then
                        Just (h.highlight (if trim then String.trim code else code) lang)
                    else Nothing                                    -- GATE 2
                Nothing -> Nothing                                  -- GATE 2 (no language)

-- lineNumbers (Code.tsx:172-189): over RAW props.code (NOT decoded).
lineNumbers : String -> String
-- post-increment push on '\n'; final push iff the last char wasn't '\n'; join "\n".

mergedShowLineNumbers : Options msg -> Bool
mergedShowLineNumbers o = if o.inline || o.wordWrap then False else o.showLineNumbers

-- the 15 --n-* vars, EXACT emission order (see upstream doc §1.5).
cssVarsFor : Theme -> Options msg -> List ( String, String )
```

`lineNumbers` in Elm: fold over `String.toList props.code` (Elm's `String.toList` is
code-point-wise, matching JS `for…of`), threading `(number, numbers, lastIsLineWrap)`.
Format numbers with `String.fromInt`, join with `"\n"`.

### 1.3 View — ONE raw Html tree

```elm
view : Theme -> Options msg -> List (Html msg) -> Element msg
view theme opts children =
    Element.html (rootNode theme opts children)
```

`rootNode` builds `<code class=... style=...>`:

- class list (ORDER): `"n-code"`, `I.classIf opts.wordWrap "n-code--word-wrap"`,
  `I.classIf (mergedShowLineNumbers opts) "n-code--show-line-numbers"`.
- style: `I.renderVars (cssVarsFor theme opts)` (the port has no `inlineThemeDisabled`; always emit).
- children:
  - when `children` is non-empty (Log's slot path) →
    `[ lineNumbersPre opts ] ++ children` (setCode returns early upstream; children are the
    caller's, untouched).
  - when `children` is empty → the **static image of setCode**:
    ```
    code = if opts.uri then (Url.percentDecode opts.code |> Maybe.withDefault opts.code) else opts.code
    html = codeHtml opts.hljs opts.language opts.trim code
    lineNums = lineNumbersPre opts
    if opts.inline then
      case html of
        Just h  -> [ lineNode "code" (innerHtml h) [] ]   -- innerHTML on the <code> itself
        Nothing -> [ Html.text code ]                     -- textContent = code
    else
      case html of
        Just h  -> [ lineNums, preNode [ innerHtml h ] ]  -- pre.__code__ innerHTML = hljs html
        Nothing -> [ lineNums, preNode [ Html.text code ] ]  -- pre.__code__ textContent = code
    ```
  where `lineNumbersPre opts = if mergedShowLineNumbers opts then [ Html.node "pre" [HA.class "n-code__line-numbers", ...] [Html.text (lineNumbers opts.code)] ] else []`.
- `lineNode "code" (innerHtml h) []` = `Html.node "code" [ innerHtml h ] []` (the `<code>` with
  raw embedded children). BUT the root is already `<code>`; the inline case sets the root's
  innerHTML, so `rootNode` for inline + no-slot must attach `innerHtml` to the root `<code>`
  and pass no children. Implement rootNode so it takes the resolved child strategy:
  ```
  rootNode: if no children && inline && Just h -> <code ... [innerHtml h] []>
            else -> <code ...> [lineNums ++ content] </code>
  ```
- `attributes` on the ROOT `<code>` — `List (Html.Attribute msg)` (a raw node cannot take an
  `Element.Attribute`; exactly `NUI.Highlight`'s note).

`preNode attrs` = `Html.node "pre" (HA.class "__code__" :: attrs) []`.

### 1.4 Theme

`NUI.Theme.Code` (manifest key `code`) — 13 vars. ⚠ dark self is NOT a common swap (the
hue/mono literals differ); VERIFY `tools/generated/code.json` light vs dark. `cssVarsFor` maps
`internalFontSize` → `${n}px` else `CodeTheme.vars.fontSize`.

## 2. `NUI.Equation`

### 2.1 Types & surface

```elm
module NUI.Equation exposing (Extracted, Options, defaults, extract, view)

type alias Extracted =
    { wrapperTag : String
    , wrapperClass : Maybe String
    , innerHtml : String
    }

type alias Options msg =
    { value : String                       -- ""
    , katex : Maybe (String -> String)     -- caller-supplied renderToString, ALREADY bound to katexOptions
    }

defaults : Options msg
defaults = { value = "", katex = Nothing }

view : Theme -> Options msg -> Element msg        -- theme ignored (empty self)
```

`s → s` katex closure: upstream `katex.renderToString(value || '', { throwOnError: false, ...katexOptions })`.
The caller bakes `{ throwOnError: false, ...opts }` into their closure — document that
`throwOnError:false` is a DEFAULT the caller's options override (upstream spreads caller opts
last). The port applies `value || ""` (`value` is already `""` in `defaults`) and the
`|| 'no katex provided'` fallback.

### 2.2 Pure extraction

```elm
extract : Maybe (String -> String) -> String -> Extracted
extract katex value =
    let
        outerHtml =
            (katex |> Maybe.map (\k -> k value)) |> Maybe.withDefault "no katex provided"
    in
    { wrapperTag = ..., wrapperClass = ..., innerHtml = ... }
```

Regexes (compile at module level with `Regex.fromString`, default flags → `multiline = False`):

- match: `^<([a-z]+)[^>]+class="([^"]+)"[^>]*>`  → `Regex.find` (leftmost), take
  `m.submatches` : `[ Just tag, Just cls ]`; absent → `wrapperTag = "span"`,
  `wrapperClass = Nothing`.
- strip forward: `^<[a-z]+[^>]*>` and backward: `<\/[a-z]+>$` via `Regex.replace re (\_ -> "") s`.
  **Do both regardless of whether the match succeeded** (upstream does).

`view` = `Element.html (Html.node ext.wrapperTag (classAttr ext.wrapperClass ++ [ innerHtml ext.innerHtml ]) [])`
where `classAttr Nothing = []`, `classAttr (Just c) = [HA.class c]`. No `n-equation` class
exists; no vars.

### 2.3 Theme — the empty-self trap (⚠ brief assumption corrected)

`equationLight.self = () => ({})`. Adding `equation` to the manifest produces
`tools/generated/equation.json = {light:{},dark:{}}`, and `gen-theme.mjs` emits a
`NUI.Theme.Equation.elm` whose `Vars` record is empty. **This BREAKS `check-theme.mjs` as
written**: `parseModule` only records a `light`/`dark` entry when it parsed ≥1 field, so
`mod.light` is `undefined` → `"no record parsed"` problem → gate fails. (Verified: running
`parseModule` on both the raw `{ \n }` and elm-format's `{}` forms returns `{}`.)

Two acceptable resolutions:
- **(recommended) omit `equation` from `manifest.mjs`** — there is no theme data to define.
  `NUI.Equation.view` still takes a `Theme` for call-site uniformity (the `NUI.Highlight`
  precedent) and ignores it; write a docstring noting upstream's empty `self`. No
  `NUI.Theme.Equation`.
- or add `equation` with a **1-line guard in `check-theme.mjs`** (`if (!Object.keys(json.light).length && !Object.keys(json.dark).length) continue`) so the empty module is skipped;
  this keeps config completeness. If taken, also confirm `gen-theme` output is `elm-format`
  clean (`type alias Vars = {}` / `light common = {}` — valid Elm, but must be re-formatted).

`tools/extract-theme.mjs` itself handles the empty case fine (it writes `{light:{},dark:{}}`).

## 3. `NUI.Log`

### 3.1 Types & surface

```elm
module NUI.Log exposing
    ( LogEvent(..)
    , Options
    , defaults
    , mergedLines
    , scrollEvents
    , styleHeight
    , view
    , wheelEvents
    )

type Panel = Top | Bottom

type LogEvent
    = RequireMoreFrom Panel      -- upstream onRequireMore('top' | 'bottom')
    | ReachTop                   -- upstream onReachTop()
    | ReachBottom                -- upstream onReachBottom()

type alias Options msg =
    { loading : Bool                       -- False
    , trim : Bool                          -- FALSE (⚠ Code's is True)
    , log : Maybe String                   -- Nothing  (String prop, undefined default)
    , lines : List String                  -- []
    , fontSize : Int                       -- 14
    , lineHeight : Float                   -- 1.25
    , language : Maybe String              -- Nothing  (highlight = Just _)
    , rows : Int                           -- 15
    , offsetTop : Int                      -- 0
    , offsetBottom : Int                   -- 0
    , hljs : Maybe Code.Hljs               -- Nothing
    , spinProps : SpinOverrides            -- {} (LogSpinProps = SharedSpinProps)
    , loadingText : Maybe String           -- Nothing → EN 'Loading'
    , loaderTransition : Maybe I.TransitionPhase   -- Nothing (house: BackTop)
    , attributes : List (Element.Attribute msg)    -- root; caller wires wheel/scroll
    }

type alias SpinOverrides =
    { strokeWidth : Maybe Int, stroke : Maybe String, scale : Maybe Float, radius : Maybe Int }
```

### 3.2 Pure mirrors

```elm
mergedLines : Options msg -> List String
mergedLines o = case o.log of
    Just s -> if s == "" then o.lines else String.split "\n" s
    Nothing -> o.lines

styleHeight : Options msg -> String
styleHeight o =
    "calc(" ++ String.fromInt (round (toFloat o.rows * o.lineHeight * toFloat o.fontSize)) ++ "px)"

-- handleScroll (Log.tsx:129-142): `<=`; requireMore BEFORE reachX; BOTH blocks can fire.
-- order of returned events: [RequireMoreFrom Top, ReachTop] ++ [RequireMoreFrom Bottom, ReachBottom]
scrollEvents :
    { scrollTop : Int, containerHeight : Int, contentHeight : Int, offsetTop : Int, offsetBottom : Int }
    -> List LogEvent

-- _handleWheel (Log.tsx:162-171): top STRICT `scrollTop === 0`, bottom `scrollBottom <= 0`.
wheelEvents :
    { scrollTop : Int, containerHeight : Int, contentHeight : Int, deltaY : Float }
    -> List LogEvent
```

`round` compiles to `Math.round` (ties toward +∞), so `round 262.5 = 263` — same as JS.
Serialization of `lineHeight`: `String.fromFloat` (`1.25` → `"1.25"`, `20` → `"20"`).

### 3.3 View

```elm
view : Theme -> Options msg -> Element msg
view theme opts =
    -- root: div.n-log with line-height + height + 6 vars in ONE style attribute
    Element.el
        ([ I.classes [ "n-log" ]
         , Element.htmlAttribute (HA.attribute "style" rootStyle)
         , Element.height Element.fill
         ]
            ++ opts.attributes
        )
        (Element.el ... ) -- children below
      |> wrapColumn
```

Root style = `line-height:{lh};height:{h};{renderVars cssVars6}` joined by `;` (upstream's Vue
array-style: object part first, then cssVars). Because a second `style` attribute would be
clobbered, build ONE string.

Children (a flex column so the absolute loader positions against the root):
1. `Scrollbar.view theme { Scrollbar.defaults | showYBar = <caller?> } [ codeEl ]` — the scroll
   seam. `NUI.Scrollbar` is caller-driven; docs to check: Log's default scrollbar is plain
   (`n-scrollbar`), so pass `Scrollbar.defaults` with `attributes`/`contentClass` as needed.
2. the loader (only when `opts.loading` OR `loaderTransition` is a leave phase — the BackTop
   "hold the leaving element" rule).

`codeEl = Code.view theme codeOpts lineChildren` where
```
codeOpts = { Code.defaults
    | internalNoHighlight = True
    , internalFontSize = Just opts.fontSize
    }
lineChildren = List.map (logLineHtml opts) (mergedLines opts)
```

`logLineHtml : Options msg -> String -> Html msg` — the static image of `NLogLine`:
```
trimmed = if opts.trim then String.trim line else line
highlighted = Code.codeHtml opts.hljs opts.language opts.trim line    -- SAME gates, per line
case highlighted of
    Just h  -> Html.node "pre" [ innerHtml h ] []        -- innerHTML
    Nothing -> Html.node "pre" [] [ Html.text trimmed ]  -- text child
```
(`highlight === (language !== undefined)`: when language is `Nothing`, `codeHtml` returns
`Nothing` ⇒ plain text — the branch collapses correctly.)

Loader =
```
Element.el
    ([ I.classes
        ("n-log-loader" :: (case opts.loaderTransition of
                              Just ph -> [ I.transitionClass "fade-in-scale-up-transition" ph ]
                              Nothing -> []))
     ])
    ( Element.el [ I.classes [ "n-base-loading" ], role/aria via htmlAttribute ]
        ( Element.el [ I.classes [ "n-base-loading__transition-wrapper" ] ]
            ( Element.el [ I.classes [ "n-base-loading__container" ] ]
                ( Element.html (Loading.spinner
                    { strokeWidth = toFloat (Maybe.withDefault 24 opts.spinProps.strokeWidth)
                    , radius = toFloat (Maybe.withDefault 100 opts.spinProps.radius)
                    , scale = Maybe.withDefault 0.85 opts.spinProps.scale
                    , stroke = opts.spinProps.stroke
                    }) )
            )
        )
        :: []
    )
    |> ... -- plus `<span class="n-log-loader__content">{loadingText}</span>` as a SIBLING
```
`loadingText = Maybe.withDefault "Loading" opts.loadingText` (upstream `locale.Log.loading`;
docstring the exact enUS path `locales/common/enUS.ts:91-93` and bytes `'Loading'`).

`NBaseLoading` defaults overridden by LogLoader: `strokeWidth 24`, `scale 0.85`; `radius`
default 100; `spinProps` spread last ⇒ overrides. Default geometry: scaledRadius
`117.64705882352942`, viewBox `235.29411764705884`, circle r `88`, dasharray `567`,
dashoffset `1848` (the `NUI.Internal.Loading` doc lists these).

## 5. Corrections to the brief's architecture (a–i), verified against bytes

- **(a) Hljs record** — agreed. Pin `highlight code language -> String` (upstream arg order);
  `getLanguage` is a Bool. Use a toy deterministic record in examples/tests.
- **(b) `innerHTML` via `HA.property`** — CONFIRMED working in jsdom: setting `el.innerHTML`
  produces real child nodes and `querySelector('.__code__')` / `querySelector('.hljs-keyword')`
  find them; `class: undefined` yields NO class attribute. Caveats: give the node NO elm
  children (the embedded subtree is outside Elm's vdom); requires elm/json (`Json.Encode`) —
  present.
- **(c) Equation katex closure** — agreed. Regex caveat: Elm `Regex` default is
  `multiline = False`, equal to JS non-`m` for `^`/`$`, **except** JS `$` also matches before a
  single trailing `\n`; if a katex output ever ends in `\n` the backward strip differs —
  docstring a `[D]` note. `Regex.replace` is global but the patterns are anchored.
- **(d) URI decode — ⚠ brief assumption FALSE.** `Url.percentDecode` needs `elm/url`, which is
  **NOT** in the library `elm.json` (only `elm/json` + `elm/regex` are). It must be added to
  `dependencies` (it is cached in `ELM_HOME` and listed in `scripts/install-elm-packages.sh`,
  so offline is fine). `examples/elm.json` lists it as `indirect` — `elm make` will flip it to
  `direct` (an expected diff). `Maybe Nothing` (malformed) → use the RAW string + `[D]` note
  (upstream `decodeURIComponent` throws an uncaught crash).
- **(e) Log pure funcs** — agreed. `wheelEvents` top uses STRICT `scrollTop === 0`
  (bottom `scrollBottom <= 0`); `scrollEvents` uses `<=` on both ends; requireMore precedes
  reachX; both blocks may fire in one event. Events as `Maybe msg` channels + `LogEvent`.
- **(f) trim asymmetry** — LOUD: Code default `True`, Log default `False`.
- **(g) LogLoader locale** — `locale.Log.loading` = `'Loading'`; `loadingText : Maybe String`
  override (Empty precedent).
- **(h) fade-in-scale-up loader transition** — the house pattern is `Maybe I.TransitionPhase`
  (BackTop, Spin). Recommend `loaderTransition : Maybe I.TransitionPhase` applying
  `I.transitionClass "fade-in-scale-up-transition"` on `.n-log-loader` (the cssr already ships
  the scoped rules). If dropped, it is a `[D]` note — but the TransitionPhase seam is cheap and
  faithful.
- **(i) theme vars** — Code = **15** (not 16; the cssr comment's `--n-line-number-color` is
  stale/unemitted), Log = **6**, Equation self = `{}` → see §2.3 (the empty theme breaks
  check-theme as-is; omit `equation` from the manifest or guard the checker).
