## 9. Module-layout precedent for BIG components

**The repo never splits a component across files.** `src/NUI/` subdirs are only `Css/` (Generated), `Theme/` (one theme module per component — auto-generated), `Internal/` (`Loading.elm` only). No `Select/Internal.elm`, no `Tabs/`, no `Dialog/`. Precedent:

- Single file, sized by complexity: `Tree.elm` 1726, `Cascader.elm` 1680, `Form.elm` 1498, `Tabs.elm` 1195, `Menu.elm` 1102.
- Internal structure = `-- SECTION` banner comments in one file: e.g. `Tree.elm` → `-- VIEW` :256, `-- PURE LOGIC` :866, `-- TREE INDEX` :1203, `-- CASCADE NORMALIZATION` :1309, `-- ICONS` :1673, `-- INTERNALS` :1690; `Cascader.elm` → `-- TYPES` :149, `-- PURE LOGIC` :359, `-- VIEW` :929, `-- MENU` :1083, `-- THEME` :1497, `-- SELECT MENU` :1534.
- Upstream's multi-file split (`DataTable.tsx`, `MainTable.tsx`, `TableParts/{Header,Body,Cell,BodyCheckbox,BodyRadio,ExpandTrigger,SelectionMenu}.tsx`, `use-{check,expand,group-header,resizable,scroll,sorter,table-data}.ts`) maps to **sections inside one `NUI.DataTable.elm`**, with shared bits (`n-base-icon`, spinner) reusing `NUI.Internal.Loading` / private helpers. If a sub-surface genuinely needs a separate public module, precedent is a *sibling top-level module* (`SelectMenu.elm`, `DrawerContent.elm`, `BaseSelection.elm`) — each exposed in elm.json; a private helper module would need a check-exposure INTERNAL entry.
