## 1. Module shape

House precedent for an **inline composite** (no overlay): `Collapse.elm`
(`view : Theme -> Options msg -> List (Item msg) -> Element msg`, `Collapse.elm:120`) and
`Menu.elm` (`view : Theme -> Options msg -> List (Option msg) -> Element msg`, `Menu.elm:273`).
Overlay components (DatePicker `874`, TimePicker `226`) use the `view`+`menu/panel` split with a
`focusDetector` sentinel and `transition : Maybe I.TransitionPhase`. **Tabs has no overlay**, so
it follows the Collapse/Menu shape: a single `view`, **no** `menu`/`panel` split, **no**
`focusDetector`, **no** transition phase. (Confirmed by the existing port: `view` at
`src/NUI/Tabs.elm:587` is `Theme -> Options msg -> List (Tab msg) -> Element msg`, `rootNode` is
plain `Html`, no transition module imported.)

Recommended / existing API (`src/NUI/Tabs.elm`):

```elm
module NUI.Tabs exposing
    ( DisplayDirective(..), JustifyContent(..), Options, Placement(..)
    , Size(..), Tab, Trigger(..), Type(..), cssVars, defaults, view )

type Type            = Line | Bar | Card | Segment          -- upstream 'bar' default
type Size            = Small | Medium | Large
type Placement       = Top | Bottom | Left | Right          -- start/end resolved by rtl
type JustifyContent  = JustifyStart | JustifyCenter | JustifyEnd
                     | JustifySpaceBetween | JustifySpaceAround | JustifySpaceEvenly
type Trigger         = Click | Hover
type DisplayDirective= ShowIf | Show                        -- 'show:lazy' not portable

type alias Tab msg =
    { name : String, label : Element msg, disabled : Bool
    , closable : Maybe Bool, content : List (Element msg) }

type alias Options msg =
    { type_ : Type, size : Size, placement : Placement, value : String
    , justifyContent : Maybe JustifyContent, closable : Bool, addable : Bool
    , trigger : Trigger, displayDirective : DisplayDirective, animated : Bool, rtl : Bool
    , tabClass : Maybe String, tabStyle : Maybe String
    , paneClass : Maybe String, paneStyle : Maybe String
    , prefix : Maybe (Element msg), suffix : Maybe (Element msg)
    , onChange : Maybe (String -> msg), onClose : Maybe (String -> msg), onAdd : Maybe msg }
```

* **Enums live locally, not in `NUI.Types`.** Precedent: component-local enums stay local
  (Collapse keeps `ArrowPlacement`/`TriggerArea`; Menu keeps `Mode`/`Placement`), while only
  cross-component enums (`Kind`, `Size`-like shared) go to `NUI.Types`. `TabsType`/`Placement`/
  `JustifyContent`/`Trigger`/`DisplayDirective` are Tabs-only → local. (`Size` is
  Tabs-specific too — keep local; `NUI.Types` has its own `Size` for other components.)
* **`Msg` set is caller-owned, not a `msg` type here** (like `Select.onSelect` / `Form`):
  the view only *emits* `onChange String` / `onClose String` / `onAdd msg`. There is no
  internal `Msg`/update loop — this matches Collapse (`onChange`) and Menu (`onSelect`).
* **No overlay → no `menu`/`panel`.** `view` returns the whole `n-tabs` (nav + pane area)
  as one `Element` (the existing `rootNode` renders `navNode :: paneNodes`).

## 2. Internal bridge usage

Existing port (`src/NUI/Tabs.elm`):
* Vars → inline `style`: `HA.attribute "style" (I.renderVars (cssVars theme opts))`
  (`rootNode`, `592-597`) — identical to DatePicker. `I.renderVars : List (String,String) -> String`
  (`Internal.elm:122`) / `I.cssVars` (`:117`) are the var-attachment helpers.
* Class emission: `I.classIf : Bool -> String -> List String` (`Internal.elm:96`) for the
  conditional `n-tabs--flex` / `n-tabs--rtl`; concatenation for the keyed modifiers.
* `I.classes` (`:105`) is available for a plain class list.
* **Theme vars path:** generated module `NUI.Theme.Tabs` exposes `type alias Vars` + `vars :
  Theme -> Vars` (`src/NUI/Theme/Tabs.elm`), produced by `tools/gen-theme.mjs` from
  `tabs/styles/light.ts` + `_common.ts`. `cssVars` reads `TabsTheme.vars theme` and matches
  upstream's `createKey` selection (size/type suffix) exactly (`cssVars`, `192-238`).
* **Generated-CSS consumption:** `NUI.Css` ships `css/naive-ui.css`, scoped under the
  `.nui-root.nui-root` marker; the element carries the `.n-tabs` BEM classes so the shipped
  rules apply — no per-component CSS in the port.
* Caller `Element`s are embedded with `Element.layoutWith { options = [ Element.noStaticStyleSheet ] }`
  + a `display:contents` wrapper (`embedChild`, `1151-1154`), the `Form`/`Collapse` precedent.

## 4. check-dom / check-classes targets

* **Existing `check-dom` target:** `{ '.n-tabs': true }` (`tools/verify/check-dom.mjs:89`) —
  asserts the root renders and carries the full inline `--n-*` set. This is the only probe the
  earlier batch added.
* **Suggested stronger probes** (for an audit; concrete per demo):
  * `.n-tabs` → `flex-basis:auto` + `--n-tab-padding` present (default `6px 0` medium/bar).
  * `.n-tabs--line-type .n-tabs-nav--line-type .n-tabs-nav-scroll-content` → `border-bottom:1px solid var(--n-tab-border-color)` (exercises `index.cssr.ts:418-420`; only line adds it).
  * `.n-tabs--segment-type .n-tabs-rail` bg = `var(--n-color-segment)`; `.n-tabs-capsule` present (empty).
  * `.n-tabs--card-type` has NO bar: assert `.n-tabs-bar` absent; assert `.n-tabs-pad` present.
  * active pane: `.n-tab-pane` count = 1 for `ShowIf`, = N for `Show` (`display:none` on inactive).
  * `--n-tab-font-size`: `16px` for `size=Large` vs `14px` medium (`_common.ts:2-4`).
  * root class set for segment includes `n-tabs--top` (placement forced) and `n-tabs-nav--segment-type`.
* **Predicted `check-classes.mjs` ALLOW entries:** **none required** if keyed classes are built
  by concatenation (as the existing port does) — the scanner only reads `"n-…"` literals
  (`check-classes.mjs:141`). If written as literals, these three would need ALLOW (they are
  emitted but have no cssr rule): `n-tabs--card-type` (`Tabs.tsx:1102`),
  `n-tabs--{small|medium|large}-size` (`Tabs.tsx:1103`), `n-tabs-nav--segment-type`
  (`Tabs.tsx:1116`) — see `tabs-1 §5`.
* Peer-component classes are avoided: inline SVG for the close/add icons and drop the scroll
  buttons, so no `n-base-icon`/`n-base-close`/`n-button*` (which would need ALLOW).

## 6. Risk list (static-render fidelity losses) — house stance cited

| Risk | Loss | Stance |
| --- | --- | --- |
| Bar geometry | `.n-tabs-bar` has no `left`/`max-width`; bar appears at `left:0` only | inert-but-rendered; documented divergence (`Tabs.elm` docstring) |
| Segment capsule | capsule renders empty at `left:0` (no `transform`) | inert-but-rendered |
| Scroll buttons / shadows / `centerActiveTab` | all measurement-driven | omitted |
| `show:lazy` | needs mutable "rendered" set | omitted (`DisplayDirective = ShowIf\|Show`) |
| Pane animation / `animated` | no translateX enter/leave; only `n-tabs-pane-wrapper` markup | markup-only |
| `onBeforeLeave` | async veto can't be expressed in a pure view | omitted |
| close `stopPropagation` | a closable+activatable card tab fires both `onClose` and `onChange` | documented divergence |
| `barWidth`, object `addable`, `tabsPadding>0`, `paneWrapperClass/Style`, `addTabClass/Style`, `tabProps`, name `number` | not ported | documented |
| scroll/overflow layout | `VXScroll`/`VResizeObserver` replaced by `n-tabs-nav-scroll-wrapper > n-tabs-nav-scroll-content` (top/bottom) and keeps `n-tabs-nav-y-scroll` (left/right) | documented |

These match the existing `src/NUI/Tabs.elm` docstring "Divergences" block (`17-50`) — i.e. the
existing port already took exactly this stance.
