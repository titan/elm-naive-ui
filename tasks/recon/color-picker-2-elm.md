## 1. The pattern model — `src/NUI/DatePicker.elm` overlay shape

`NUI.ColorPicker` is an overlay (trigger + caller-mounted popover body), so DatePicker is
the template, **not** the inline-composite shape of Collapse/Tabs.

**1.1 Imports / module skeleton.** `src/NUI/DatePicker.elm:163-175` — imports
`Element`, `Html`/`Html.Attributes`/`Html.Events`, `NUI.Input`, `NUI.Button`,
`NUI.Internal as I`, the pure engine `NUI.Internal.DateTime as DT`, `NUI.Scrollbar`,
`NUI.Theme exposing (Theme)`, `NUI.Theme.DatePicker as DPTheme`, `Svg`, `Time`.
The generated theme module is imported aliased (`DPTheme`) and read via `DPTheme.vars theme`.

**1.2 `Options msg` + `defaultOptions`.** One record of every knob
(`DatePicker.elm:334-410`), with `defaultOptions : Options msg` inlining upstream's
defaults (`:415-490`). Runtime/behaviour fields are caller-owned `Maybe` msg/state
(`show`, `onUpdateShow`, `transition`, …). Do the same for ColorPicker
(`value`, `show`, `modes`, `showAlpha`, `showPreview`, `swatches`, `actions`,
`disabled`, `size`, `onUpdateValue`, `onConfirm`, `onClear`, `transition`, …).

**1.3 `view` (trigger) vs `panel` (body) split.**
- `view : Theme -> Options msg -> Element msg` (`DatePicker.elm:874-881`) emits
  `div.n-date-picker --disabled/--range`, `style = I.renderVars (triggerVars theme)`,
  body = a single embedded `NUI.Input`.
- `triggerClasses` (`:884-888`) and `triggerVars` (`:891-900`) are tiny local helpers;
  `triggerBody`/`singleInputOptions` (`:903-934`) build the `NUI.Input` options record.
- `panel : Theme -> Options msg -> Element msg` (`:1132-1134`) delegates to a private
  `panelWith : Theme -> Options msg -> Maybe CalendarSide -> Element msg` (`:1140-1151`)
  that renders `div.n-date-panel`, `HA.tabindex 0`, `style = I.renderVars (panelVars …)`,
  body = `bodyFor … ++ actionsSlot … ++ [ focusDetectorNode ]`.
- `bodyFor` (`:1312-1347`) is the per-type dispatch; `panelClasses` (`:1154-1166`) builds
  the class list. **This is the shape to copy**: a public `view` (trigger) plus a public
  `panel` (body), caller mounts the panel itself when `show` is True.

**1.4 focusDetector sentinel.** `focusDetectorNode` (`DatePicker.elm:1303-1305`) =
`Html.div [ style "width:0;height:0", tabindex 0 ] []`; appended as the **last child** of
the panel (`:1150`). Purely inert, no class, no msg.

**1.5 `transition : Maybe NUI.Internal.TransitionPhase`.** The panel adds the class via
`I.transitionClass "fade-in-scale-up-transition" phase` when `Just phase`
(`DatePicker.elm:1160-1166`). `TransitionPhase` and `transitionClass` live in
`src/NUI/Internal.elm:35` / `:47`; `isLeavePhase` at `:77`. ColourPicker upstream uses the
same `fade-in-scale-up-transition` name (`src/color-picker/src/styles/index.cssr.ts:15`
imports `fadeInScaleUpTransition`) → same class string.

**1.6 cssVars plumbing.** Two idioms:
- Raw `Html`: `HA.attribute "style" (I.renderVars vars)` (`DatePicker.elm:879`, `:1146`).
- elm-ui `Attribute`: `I.cssVars vars` (`src/NUI/Internal.elm:117`), which calls
  `I.renderVars` (`:122`) and **drops `"initial"` and empty values** (upstream's "unset"
  marker). Pass themed vars and literal declarations in ONE list (never a second `style`).
- Class helpers: `I.classIf` (`Internal.elm:96`), `I.classes` (`:105`).
- `panelVars` (`DatePicker.elm:1211-1302`) is the pattern: a `List (String, String)` read
  field-by-field from `DPTheme.vars theme` in **upstream declaration order**. ColourPicker
  upstream emits 10 vars in one `cssVarsRef` (`src/color-picker/src/ColorPicker.tsx`
  `cssVarsRef`, keys `--n-bezier/--n-text-color/--n-color/--n-panel-font-size/--n-font-size/
  --n-box-shadow/--n-border/--n-border-radius/--n-height/--n-divider-color`) — port that
  list verbatim, with `height`/`font-size` selected by `createKey('height'|'fontSize', size)`.

**1.7 Theme var lookup.** `DPTheme.vars : Theme -> Vars` from a **generated** module
(`src/NUI/Theme/DatePicker.elm`); generated by `tools/gen-theme.mjs` (see §2).
`size` handling is a `T.Size` field (`DatePicker.elm:352`) resolved by `createKey`
(mirror upstream). Common vars are read off `theme.common.<field>` directly (e.g.
`theme.common.cubicBezierEaseInOut`, `DatePicker.elm:897`).

**1.8 Embedding elm-ui children in raw `Html`.** `embedHtml`
(`DatePicker.elm:2978-2982`) = `Element.layoutWith { options = [ Element.noStaticStyleSheet ] }`
+ a `display:contents;font:inherit;color:inherit` wrapper. Needed for `NUI.Input`/`NUI.Button`
inside the raw panel tree; ColourPicker needs it for its `NInputGroup`/`NInput`/`NButton`.

**1.9 Sizing/bounded panel.** DatePicker hardcodes nothing per-size in the panel; the
trigger passes `opts.size` into `NUI.Input` (`singleInputOptions`, `DatePicker.elm:925`).
ColourPicker's `size` is consumed only through the generated vars (`height{Small,Medium,Large}`,
`fontSize{Small,Medium,Large}`) — see `src/color-picker/styles/light.ts:32-34`.

**1.10 The pure-engine module as precedent.** `src/NUI/Internal/DateTime.elm` (2226 L) is
`module NUI.Internal.DateTime exposing (…)` (`:1-41`), an **unexposed internal API**
(`:48` "imports only `elm/core` and `elm/time`"), reached via DatePicker/TimePicker.
Its docstring (`:43+`) states the contract: pure civil math + a date-fns token subset.
**This is the home template for colour maths** (`src/NUI/Internal/Color.elm`?), BUT see
§5 — a hand-written `src/NUI/Theme/Color.elm` already exists and overlaps.

## 2. Build / tooling wiring — what a new component requires

Exact, ordered, with file paths and cites. **The `138f844` prep commit is the reference**
(`git show --stat 138f844`): manifest entries + `tools/generated/*.json` + `css/naive-ui.css`
+ `src/NUI/Css/Generated.elm` + `src/NUI/Theme/<Comp>.elm` + 2 `elm.json` lines.

1. **Manifest entry** — `tools/manifest.mjs`. Component keys are kebab-case objects
   `{ cssr: [...], theme: '...' }`; see `'time-picker'` (`manifest.mjs:542`) and
   `'date-picker'` (`:557`). For ColorPicker:
   ```js
   'color-picker': {
     cssr: ['color-picker/src/styles/index.cssr.ts'],
     theme: 'color-picker/styles/light.ts'
   ```

   - `cssr` paths are relative to `NAIVE_UI_SRC` (`manifest.mjs:4-6`). ColourPicker has
     exactly one cssr file and **no `rtl.cssr.ts`** (verified: upstream
     `src/color-picker/src/styles/` holds only `index.cssr.ts`).
   - **The kebab key is load-bearing**: `check-theme.mjs` maps module name `ColorPicker`
     back to `color-picker.json` via camel→kebab (`check-theme.mjs:59` `jsonNameFor`); a
     camelCase key silently skips the theme gate (warning in `manifest.mjs` at the
     `'auto-complete'` entry).
   - Add a `//` comment describing the DOM family (house style: every entry has one).

2. **Run the extractor**: `cd tools && npm run extract` (`tools/package.json:6` →
   `extract-all.mjs`). `NAIVE_UI_SRC` defaults to `/home/titan/Works/elm/naive-ui`
   (`extract-css.mjs:16`, `extract-theme.mjs:12`). It runs, in order
   (`tools/extract-all.mjs`):
   - `extract-theme.mjs` → **`tools/generated/<key>.json`** (`extract-theme.mjs:184-…`,
     writes `{ light, dark, refs }`); for ColourPicker, `tools/generated/color-picker.json`
     (theme `self` = 13 vars: panelFontSize, boxShadow, color, textColor, borderRadius,
     border, height{Small,Medium,Large}, fontSize{Small,Medium,Large}, dividerColor —
     `src/color-picker/styles/light.ts:15-39`).
   - `extract-css.mjs` → **`css/naive-ui.css`** (`extract-css.mjs:180`) AND
     **`src/NUI/Css/Generated.elm`** (`:200`); each rule scoped under `.nui-root.nui-root `
     (`:18`). ColourPicker currently contributes **0** `n-color-picker` rules (verified
     `grep -c n-color-picker css/naive-ui.css` = 0).
   - `gen-theme.mjs` → **`src/NUI/Theme/Common.elm`** + **`src/NUI/Theme/<Comp>.elm`**
     (`gen-theme.mjs:57`, `:96`), i.e. `src/NUI/Theme/ColorPicker.elm` with
     `type alias Vars`, `vars : Theme -> Vars`, `light`/`dark : Common -> Vars`.
   - `elm-format` on `src/NUI/Theme` + `src/NUI/Css/Generated.elm` (`extract-all.mjs:22`).
   - `npm install` is required only if `tools/node_modules` is stale (it is present now);
     the brief forbids installs.

3. **Expose the generated modules in `elm.json`** — this is what the brief calls the
   "exposure site". It is **`elm.json`'s `exposed-modules` list** (`elm.json:9-…`), NOT
   `src/NUI/Theme.elm`. `check-exposure.mjs` (`scripts/verify.sh:48`) requires every module
   under `src/` to be listed (minus a fixed INTERNAL set). The `138f844` prep commit added
   exactly `"NUI.Theme.DatePicker"` and `"NUI.Theme.TimePicker"` (`git show --stat 138f844`
   → `elm.json | 2 +`). So: prep commit adds **`NUI.Theme.ColorPicker`**; the later `feat`
   commit adds **`NUI.ColorPicker`**. (Missing exposure = package-mode `elm make` silently
   skips the module — the gate exists precisely for this, `check-exposure.mjs` docstring.)
   If a new `NUI.Internal.Color` engine module is created, add it to the `INTERNAL` set in
   `tools/verify/check-exposure.mjs:13-18` (next to `'NUI.Internal.DateTime'`) — OR expose
   it; do not leave it unlisted.

4. **`check-dom.mjs` target** — add `'.n-color-picker': true` / `'.n-color-picker-panel': true`
   to the `targets` object (`tools/verify/check-dom.mjs:20-167`; entries end at

   `cssVarsRef` on **both** the trigger (`ColorPicker.tsx` `triggerProps.style`) and the panel
   (`ColorPicker.tsx` `renderPanel` `style`) → both need `true`.

5. **`check-classes.mjs` ALLOW-list** — `const ALLOW = new Set([…])` (`check-classes.mjs:16`).
   The scanner reads only quoted `"n-…"` string literals in `src/NUI/*.elm`

   e.g. `check-classes.mjs` `n-date-picker--range` citing `DatePicker.tsx:1091`). ColourPicker

   (`index.cssr.ts` `cB('color-picker-checkboard')`), so NOT an ALLOW; watch for
   `n-color-picker__value`/`__fill` (styled) vs any unstyled marker.

6. **Gate after the commit**: `ELM_HOME=/tmp/elm-home ./scripts/verify.sh` → 8/8
   (`scripts/verify.sh:31-66`). Run it in **foreground chunks** (backgrounding dies in this

## 5. Existing colour code — do NOT duplicate

**The only colour module is `src/NUI/Theme/Color.elm`** (hand-written, exposed as
`NUI.Theme.Color` in `elm.json`). Contents:
- `Rgba` alias (`:16`), `parse` — `#rgb`/`#rrggbb`/`rgb()`/`rgba()` only (`:26`).
- `toCss` (`:162`), `composite` (`:177`), `changeColor` (`:199`),
  `createHoverColor` (`:209`), `createPressedColor` (`:219`).
- It is a port of **`seemly`'s RGB/alpha helpers only** (`Color.elm:11-14` docstring).

Used by `NUI.Theme.setPrimary` (`src/NUI/Theme.elm:61-75`), `Button.elm:325/400/406/543`,
`Cascader.elm:1528` (`changeColor v.menuColor 0.75`), etc.

**What is MISSING for ColorPicker** (upstream `src/color-picker/src/utils.ts` needs from
seemly): HSV↔RGB↔HSL conversions, `hsla`/`hsva`/`rgba` string parsers, and the
`toHex{,a}String`/`toRgb{,a}String`/`toHsl{,a}String`/`toHsv{,a}String` serializers
(`utils.ts:1-14, 74-146`), plus `normalizeHue/normalizeAlpha` (`utils.ts:60-68`) and
`getWCAGContrast`/`rgb2luminance` (`utils.ts:32-58`). None of this exists in the repo
(verified: `grep` for `hsv|hsl` in `src/**/*.elm` finds only doc-comment mentions).

**Recommended home / decision point.** Create **`src/NUI/Internal/Color.elm`** as the pure
engine (mirroring `NUI.Internal.DateTime`): conversions + serializers + normalizers + WCAG.
Do **not** move `NUI.Theme.Color` — it is `seemly`'s alpha/theme-derivation subset used by
the theme layer; keep the two roles separate (theme derivation vs. color-picker maths).
Add `NUI.Internal.Color` to the `INTERNAL` set (`check-exposure.mjs:13-18`). If instead you
extend `NUI.Theme.Color`, note it is **public** — that widens the API surface.

## 7. Input seams — decision point (recommended: NO new seams)

**What DatePicker added to `NUI.Input`** (all default-off, additive):
- Focus control: `passivelyActivated` / `activated` / `internalForceFocus` /
  `textDecoration` / `attrSize` / `onFocus` / `onBlur` / `clearIconPlaceholder`
  (`src/NUI/Input.elm` options fields `:208-216`; docstring `:92-135` defaults `:250-257`).
- **PAIR mode**: `pairValue` / `pairPlaceholder` / `pairTextDecoration` / `separatorNode` /
  `onPairInput` + the `PairSource(..)` type (`Input.elm:178`, `:216-220`, docstring `:117-131`).

**Does ColorPicker need them?** No.
- ColourPicker's trigger is a **custom `div.n-color-picker`**, not an `NInput`
  (`src/color-picker/src/ColorPickerTrigger.tsx` render — plain div + fill layers), so the
  pair/focus seams are irrelevant.
- Its numeric inputs are **plain `NInput`s** wrapped in an **`NInputGroup`**
  (`ColorInput.tsx` `NInputGroup` + `ColorInputUnit`, and `ColorInputUnit.tsx` renders a bare
  `NInput size="small"`). The port already ships a group API:
  `NUI.Input.group` / `NUI.Input.groupLabel` (`src/NUI/Input.elm:7-8`, `:990-1030`).
- So the only `NUI.Input` reuse is `Input.view` + `Input.group` — **already exposed**.
  **Decision: ColorPicker adds no `Input.elm` seams.** (Contrast with DatePicker, which
  needed the pair + focus seams because its trigger *was* an `NInput`.) Confirm against the
  upstream lane's read of `ColorInputUnit.tsx` before closing this.

## 8. Upstream ColourPicker structure & risks

Panel tree (upstream `src/color-picker/src/ColorPicker.tsx` `renderPanel`):
`div.n-color-picker-panel` (fade-in-scale-up class, cssVars) >
`div.n-color-picker-control` > [ `Pallete`, `div.n-color-picker-preview`
(`__sliders` with `HueSlider` + optional `AlphaSlider`, optional `ColorPreview`),
`ColorInput` (`div.n-color-picker-input` + `__mode` + `NInputGroup`),
optional `ColorPickerSwatches` ] + optional `div.n-color-picker-action` (`NButton`s).
Trigger (`ColorPickerTrigger.tsx`): `div.n-color-picker[--disabled]` > `__fill` >
[`div.n-color-picker-checkboard`, absolute bg layer, `__value` label].

Risks / what does NOT map cleanly onto the DatePicker pattern — each needs a call:

| # | Risk / gap | Grounding | Recommended call |
| --- | --- | --- | --- |
| R1 | **Drag state is DOM-global.** Pallete + HueSlider + AlphaSlider bind `document` `mousemove`/`mouseup` on `mousedown` and compute from `getBoundingClientRect()` | `Pallete.tsx:34-52`; `HueSlider.tsx:36-60`; `AlphaSlider.tsx:35-58` | Caller-owned (house rule): emit `onMouseDown`-style msgs with the geometry the caller can compute, or expose pure `svFromPoint`/`hueFromPoint`/`alphaFromPoint` helpers + a `Maybe TransitionPhase`-like drag flag. Document the punt. |
| R2 | **No canvas gradients.** Pallete/sliders are pure CSS-gradient layers + a positioned handle (no `<canvas>`), so they *do* render statically | `Pallete.tsx` render (two `linear-gradient` layers); `HueSlider.tsx:11` `GRADIENT` const; `AlphaSlider.tsx` `railBackgroundImage` | Low risk — faithful static render is achievable. Only the handle `left/bottom: calc(% …)` from caller state. |
| R3 | **Swatch name→hex needs a canvas / DOM.** `ColorPickerSwatches` resolves CSS colour names via `document.createElement('canvas')` | `ColorPickerSwatches.tsx:24-32` (`getHexFromName`) | Punt the named-colour resolution: require swatches be valid CSS colours, or ship a small name→hex table; document divergence. Swatch select is otherwise pure (`.n-color-picker-swatch`, `__fill` background). |
| R4 | **Undo/redo (`internalActions`) is a mutable stack.** `undoStackRef`/`valueIndexRef` + `doUpdateValue` | `ColorPicker.tsx` `undoStackRef`, `undo`, `redo` | Caller-owned model (no internal Model in this port — `docs/ARCHITECTURE.md` "Runtime behaviour"). Emit `onUndo`/`onRedo` only if a surface is wanted; else omit (upstream default `internalActions` is undefined). |
| R5 | **`mode` cycling + `modes`.** Clicking `__mode` advances the displayed mode | `ColorPicker.tsx` `handleUpdateDisplayedMode` | Caller-owned (`onUpdateMode` msg) + pure `deriveDefaultValue`/`getModeFromValue` helpers. |
| R6 | **WCAG contrast label colour.** Trigger label colour = white/black from `getWCAGContrast(hsla)` | `ColorPickerTrigger.tsx:23-28`; `utils.ts:32-58` | Port `getWCAGContrast`/`rgb2luminance` into the pure engine (R5/§5). Pure, pinnable. |
| R7 | **Peers `Input`/`Button` theme overrides.** Upstream passes `mergedTheme.peers.Input` / `.Button` overrides into the embedded components | `ColorInputUnit.tsx` `theme={mergedTheme.peers.Input}`; `ColorPicker.tsx` action `NButton theme={…peers.Button}` | Use the existing `NUI.Theme.Input` / `NUI.Theme.Button` vars (house precedent: DatePicker embeds `NUI.Input`/`NUI.Button`); no peer-override plumbing is invented. |
| R8 | **Locale strings.** Actions use `localeRef` confirm/clear/undo/redo | `ColorPicker.tsx` action buttons | Port ships no locale layer → hardcode English literals (DatePicker precedent: `"Now"`/`"Clear"`/`"Confirm"` at `DatePicker.elm` `clearButton`/`suffixButton`). |
| R9 | **`size` var selection.** `height`/`fontSize` picked by `createKey(…, mergedSize)`; form-item size default is `medium` | `ColorPicker.tsx` `cssVarsRef`; `styles/light.ts:32-34` | Pure cssVars fn keyed by `T.Size`; pin the size→var selection (like Tabs' `createKey` pins). |
| R10 | **Trigger carries the vars (unlike DatePicker).** Upstream sets `style=cssVars` on the trigger AND the panel | `ColorPicker.tsx` `triggerProps.style` + `renderPanel` `style` | `check-dom` targets: `.n-color-picker` true **and** `.n-color-picker-panel` true (both 10-var sets). |

**Overall call:** ColourPicker fits the DatePicker overlay pattern well (trigger + caller-
mounted panel + focusDetector + `TransitionPhase` + cssVars). The genuinely new work is the
**pure colour engine** (§5) and the **caller-owned drag algebra** (R1). Sequence it like the
time-picker/date-picker batch: `prep` (manifest + extract + `NUI.Theme.ColorPicker` exposure)
→ `feat` (`NUI.ColorPicker` + `NUI.Internal.Color` + examples + README + check-dom) →
`test` (pins-first eq + DOM probes) → `fix` (oracle audit; R1/R3 divergences become
`[oracle D]` docstrings).
